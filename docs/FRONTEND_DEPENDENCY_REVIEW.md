# Editorial browser dependency review

The React, TypeScript, Vite, Vitest and Playwright versions and resolved dependency graph are retained. The package/lockfile root version changes from 0.2.0 to 0.3.0; no router, animation, analytics or hosted widget dependency is added. Fonts are licensed self-hosted static assets with their own ledger.

The refreshed full npm audit reports **GHSA-fc5q-39xc-vjpf / CVE-2026-112366**, newly reviewed on 17 November 2026, in `picomatch` 4.0.7. At inspection the official npm latest is 4.0.7 and the [GitHub advisory](https://github.com/advisories/GHSA-fc5q-39xc-vjpf) lists no patched version. The linked [upstream PR 194](https://github.com/micromatch/picomatch/pull/194) explicitly says it does not generally fix the single-branch repeated-extglob issue. It is not adopted as a security fix. The original audit output is retained in the CI artifact; the twelve affected dependency-chain entries are not twelve independently discovered browser flaws.

This is a **remaining development-tool issue**, not a zero-vulnerability audit. Picomatch belongs to Node build/test globbing tooling. The delivered static app and local inference worker do not import it; no user-controlled message becomes a build glob. Production npm dependencies are React and React DOM. Trusted repository-owned glob patterns are used in an ephemeral build/test environment. There is no production Vite server or server-side input endpoint.

`web/scripts/audit-dependencies.mjs` preserves the complete full audit and the production-only audit. It fails on an unavailable/malformed audit, any production finding, or any different direct advisory. The exact known development finding is explicitly reported with its exposure and unresolved upstream status. This implements specification §46’s required distinction between production-reachable and development-tool findings, rather than hiding the failed full audit behind a successful build. Upgrade to a compatible official fixed release when one exists; do not force-downgrade the whole toolchain or claim an unverified patch fixes the CVE.
